# AI 运维控制台 · SSH 多主机 + AI 诊断

一个**纯本地**的 Web 控制台：登录后由你自己决定连接哪台 Linux，用 SSH 用户名/密码建立
真正的交互式终端（支持 Tab 补全、vim、top），下方挂「AI 运维」面板，让 AI 自动执行诊断命令、
分析日志、巡检系统、讲解命令用法，并把每一步（命令 / 风险 / 输出 / 退出码 / 耗时）列出来；
危险操作**先弹确认**再执行。

> 当前版本**不部署、不上传**，所有文件都保存在本机 `ai-ops-console/` 目录内，按类别分文件夹存放。

---

## 一、为什么有个后端

浏览器里的纯 HTML **无法直接建立 SSH TCP 连接**（没有原生 socket），也不能把 AI 的 API Key
放在前端（会泄露 + 跨域）。所以本工具是一个本地小服务：

```
浏览器 (HTML/JS + xterm.js) ──HTTP/SSE──> 本机 FastAPI 后端 ──SSH(paramiko)──> 多台 Linux
                                              │
                                              └──HTTPS──> AI API (DeepSeek)
```

- 登录鉴权在最外层，未登录访问任何页面或 API 都会被拦下；
- SSH 密码用 Fernet 加密存在本机 `config/config.json`；
- API Key **只存后端**，前端只显示脱敏值；
- 默认只监听 `127.0.0.1:8848`，不暴露到局域网；
- 交互式终端走「SSE 输出流 + POST 输入流」双通道，无需 WebSocket 组件，**零额外安装**。

## 二、启动

**Windows**：双击 `scripts/start.bat`
**Linux / macOS**：`bash scripts/start.sh`

或手动：

```bash
cd ai-ops-console
pip install -r requirements.txt     # 本地 Python 3.9+ 即可，通常已装齐
python scripts/console.py           # 交互式控制台（推荐，可 reload/stop）
# 或直接 python -m backend.app（无菜单，Ctrl+C 停止）
```

浏览器打开 **http://127.0.0.1:8848** → 自动进入登录页。

**双击 `start.bat` 后的窗口行为（Windows）——交互式服务控制台**：

- 脚本先自检 Python、依赖与 8848 端口，窗口依次显示 `[1/3]`、`[2/3]`、`[3/3]`，提示全为英文、不再出现乱码；
- 之后进入**交互式服务控制台**：服务作为子进程运行，窗口底部出现 `console>` 提示符，可反复操作而**不必关闭窗口重开**：

  | 输入 | 作用 |
  | --- | --- |
  | `r` / `reload` | **重载服务**：停掉旧进程再起新的，窗口不关（改了配置/代码后最常用） |
  | `x` / `stop` / `disconnect` | **断开服务**：停止服务，窗口保留，随时可再 `b` 启动 |
  | `b` / `start` | 重新启动服务 |
  | `o` / `open` | 打开登录页浏览器 |
  | `st` / `status` | 查看当前运行状态（RUNNING/STOPPED、PID、URL） |
  | `h` / `help` | 显示命令清单 |
  | `q` / `quit` | 停止服务并退出控制台（窗口才会关闭） |

- **服务运行期间该窗口保持打开**，但不再等于"服务本身"——服务在独立子进程，窗口只是控制器；关窗或按 **Ctrl+C** 都会自动停掉服务；
- 服务启动约 3 秒后会**自动打开默认浏览器**，无需手动输入地址；重载后如需再开浏览器用 `o`；
- 若 **8848 已被占用**（例如已经有一个服务在跑），窗口提示 `Port 127.0.0.1:8848 is already in use`，**直接打开浏览器**、不会启动第二个实例，然后自动退出；
- 若 Python 或依赖缺失，窗口会**停住并显示英文错误**（例如提示执行 `pip install -r requirements.txt`），按任意键才退出，方便照着提示排查，**不再一闪而过**。

控制台源码在 `scripts/console.py`，命令解析与服务状态机可用 `scripts/test_console.py` 单测（假进程、不占端口）。

依赖：`fastapi` `uvicorn` `paramiko` `requests` `cryptography` `pillow`（本机均已具备）。
前端用的 `xterm.js` / `addon-fit` 已下载到 `frontend/vendor/`，**完全离线可用，不需要 npm、不连 CDN**。

## 三、登录

| 项 | 值 |
| --- | --- |
| 用户名 | `admin` |
| 密码 | `ChangeMe_123456`（固定，首次启动初始化） |
| 验证码 | 服务端生成的 **PNG 图片验证码**，4 位字符，不区分大小写 |

安全细节：

- 密码**不以明文落盘**：配置里只保存 PBKDF2-HMAC-SHA256（20 万轮）+ 随机盐的散列；
- 验证码一次性、5 分钟有效、带干扰线与噪点、校验后即作废，点击图片可换一张；
- 连续输错 5 次锁定 60 秒；登录态 8 小时有效，Cookie 为 `HttpOnly + SameSite=Lax`；
- 未登录访问 `/` 跳登录页，访问 `/api/*` 返回 401，前端会自动跳回登录页；
- 右上角「⏻ 退出」可主动注销。

**改密码**：`python scripts/set_password.py`（交互式输入两次）或 `python scripts/set_password.py 新密码`。
改完后所有已登录会话立即失效。

> 若忘记密码，删除 `config/config.json` 中 `auth` 段后重启服务，会重新初始化为默认密码
> （注意：这会清空该文件中的其它配置，请先备份）。

## 四、首次使用三步

1. **添加主机**：左侧「+ 添加」→ 填 名称 / IP / 端口 / 用户名 / **密码** → 点「测试连接」→「保存」。
   可反复添加多台，每台主机一个独立终端会话，互不干扰。
2. **自己决定连哪台**（v1.2 起）：**登录不会自动连接任何主机**。左侧主机列表里每台右侧都有
   一个 **「连接」** 按钮，点它才建立 SSH 会话；已连接的主机按钮变成 **「断开」**，点一下即可关闭。
   只点击主机条目只是把它设为「目标主机」，终端区会提示「点击左侧该主机的『连接』按钮才会建立 SSH 会话」。
   终端标签页也**只显示已连接的会话**。
   - **修改主机**：每台主机右侧还有 **「修改」** 按钮，可改 名称 / IP / 端口 / 用户名 / 密码（密码留空表示不改）。
   - **删除主机**：右侧 `×` 按钮，二次确认后删除。
   连上后是**真正的交互式终端**（xterm.js + PTY）：
   - 直接在终端里输入，没有单独的命令输入框；
   - **Tab 补全**、`↑↓` 历史、`Ctrl+C` 中断、`Ctrl+D` 退出、`Ctrl+L` 清屏都可用；
   - **vim / vi / top / less / htop** 等全屏程序正常渲染，窗口缩放会自动同步 PTY 尺寸；
   - 支持粘贴（Ctrl+Shift+V / 右键），右上角 `⛶` 可放大终端，`⟳` 重连，`⌫` 清屏。
3. **开始执行**：在下方「AI 运维」面板写好要求 → 点「▶ 开始执行」。

| 控件 | 作用 |
| --- | --- |
| 目标 | 选择要诊断的主机 |
| AI 接入 / 模型 | 选 AI 服务商与模型（⟳ 可从 API 实时拉取模型列表） |
| 只读模式（默认开） | 只允许 cat/grep/journalctl/df/ps/ss/systemctl status 等只读命令，非只读命令直接拦截 |
| 自动批准 | 关：写/危险命令逐条弹确认；开：自动执行（生产环境慎用） |
| 命令执行 / AI 问答 | 前者连主机真跑命令；后者纯讲解，不连主机 |

> 注：原「最大重试」输入框已移除。Agent 默认排查步数上限放宽为 60 步（仅作防死循环兜底，正常诊断都会自然跑完并输出完整结论），界面上不再展示步数上限，进度条只显示「已执行 N 步」。如需调整兜底上限，改 `backend/app.py` 中 `max_retry` 的默认值即可。
| 清空 / 重置 | 清空结果；任务卡住时可一键停止并恢复按钮 |

快捷任务已内置：日志异常分析、全面系统巡检、/ 分区满定位、服务异常排查、网络与端口、vim 参数怎么用。

## 五、AI 结果的呈现方式

- **结构化结论**：AI 结论按 `【现象】【证据】【根因】【建议】【验证方法】` 自动分节，
  列表项、行内命令都会单独着色。
- **格式容错（静默）**：推理模型偶尔会输出畸形 JSON（缺花括号、键名带方括号、中文引号、被截断），
  后端会逐级修复并自动提取出结论与命令；**内部容错不再弹「已自动修复回复格式」之类的提示打扰你**，
  实在无法解析时按纯文本清洗后完整呈现，不会把原始 JSON 当作错误抛到界面上。
- **结论不会只剩半句**：推理模型可能先耗尽 token 生成思维链，导致正文被拦腰截断
  （例如只剩「该机属于」）。后端会检测 `finish_reason=length` 与可疑结尾，自动续写补完整；
  同时提高了各接口的默认 `max_tokens`。
- **富文本清洗**：答案里残留的 `**`、Markdown 代码围栏、孤立分隔线、重复标题、末尾空标题、
  末尾半句都会被独立渲染模块 `frontend/assets/render.js` 清理；内容确实不完整时会显示一条
  温和的不完整提示，而不是把半句话当成结论。
- **友好提示**：API 失效、余额不足、限流、超时等会翻译成人话并给出处理建议，
  技术细节放在「查看技术细节」里折叠。
- **单一进度条 + 心跳**：诊断过程只保留一条进度条；AI 推理、命令执行、等待审批期间
  每 3 秒推送一次心跳，进度条呈呼吸动画并显示已等待时长，**不会再出现「看起来卡死」**。
- **问答不会假卡住**：答案返回后 `answer_done` / `done` 会清掉「AI 正在思考（已等待 Ns）」进度条，
  并复位运行按钮；异常断流时 `finally` 也会做同样的清理。
- **可折叠思考过程**：思维链整理成短句段落，默认收起，点开才看全文。
- **步骤卡片完整可读**：命令全文换行显示（带「复制」按钮）、长输出默认收起但可一键
  「展开全部输出」、结论卡片不截断；整个步骤区不再有双层嵌套滚动，内容全部看得全。
- **AI 问答**：点击后立即显示「AI 正在思考…」，答案流式增量渲染（节流防闪烁），
  推理模型首字较慢时会提示「模型仍在推理」；若检测到回答被截断，会额外提示「回答可能未完整生成」。

## 六、危险命令审批（重点）

当 AI 给出写操作/危险命令时，**页面底部会弹出固定在视窗内的醒目确认条**，
显示完整命令、风险原因、倒计时，以及「批准执行 / 拒绝」两个按钮：

- 确认条固定在视窗内，**不会随步骤区滚动而消失**，也不会因为输出太长被挤出可视区；
- 后端等待审批期间持续推心跳，前端倒计时同步校正；
- **120 秒未确认自动拒绝**并继续分析，绝不无限期挂起；
- 点「停止」「清空 / 重置」或关闭页面，都能让流程收尾，按钮不会被永久禁用；
- 前端另有 90 秒静默看门狗作为兜底，异常断流时自动恢复按钮。

只读模式下写命令会被直接拦截，连续被拦截 2 次后会要求 AI 立即给出结论，避免空转。

> **关于「阶段结论 · 已达最大步数（N 步）」**：这不是报错，而是 Agent 跑满了步数上限（后端固定 20 步）。
> 此时它会基于**已收集到的证据**给出一份**阶段性结论**（明确标注不是完整结论），
> 并在正文里说明可以「调大步数上限后重跑」或「缩小问题范围」。旧版标题
> 「AI 结论与建议（已达最大步数）」容易让人误以为是错误，v1.2 起已改成上述写法并补充解释。

## 八、安全设计

- **最外层登录闸门** + 图片验证码：所有页面与 API 默认需登录。
- **只读模式默认开启**，命令按 `;` `&&` `||` `|` 拆段逐条评估（引号感知，不会把 `grep -E 'a|b'` 拆错）。
- **危险命令清单**：rm/mv/dd/mkfs/reboot/shutdown/kill -9/systemctl restart/chmod/chown/
  iptables/sed -i/`>` 重定向/管道执行远程脚本/DDL/DML 等，一律需人工批准。
- `fallocate` / `mkswap` / `swapon` 等会给出明确风险原因；`swapon --show` 等查看类命令
  按只读处理，不再误判为写操作。
- `docker ps --format` 这类命令里的 `--format` **不会**再被误当成「格式化磁盘」拦截；
  只有 `mkfs*` / `format /dev/...` 这类真正格式化才判危险。
- 未识别命令按「写操作」保守处理；命令输出自动截断（防超 token），超时 45s 自动终止。
- SSH 密码加密落盘；登录密码只存散列；API Key 不下发；报告与日志不打印凭据。
- 建议保持 `server.host = 127.0.0.1`。

> ⚠️ 本次 API Key 曾以明文出现在对话中，建议在平台**重置一次**，重置后在「⚙ API修改」里更新并点「测试 API」。

## 十、常见问题

**连不上主机？** 先确认你点了该主机的「**连接**」按钮（登录不会自动连），再点「测试连接」看报错：
`Connection timed out` 查网络/防火墙/端口；`AuthenticationException` 查用户名密码；
确认目标机 `sshd` 在跑、允许密码登录。

**vim 显示错乱 / 输入不了？** 请确认浏览器已刷新到最新版本（F5 强制刷新），
并在终端里直接输入 `vim 文件名`；不要找独立命令框——现在整个深色区域就是终端。

**AI 没反应？** 「⚙ API修改 → 测试 API」；确认网络能访问 `api.deepseek.com`、Key 有余额、
模型名与 `/models` 返回一致（可点「拉取模型」）。推理模型首字较慢属正常，进度条会持续呼吸。

**只想问命令怎么用？** 切到「AI 问答」页签，不需要连主机，也不需要点「连接」。

**点开始没反应 / 按钮灰着？** 说明上一轮任务还在运行（常见于等待确认时）。
看页面底部是否有确认条；也可点「停止」或「清空 / 重置」立即恢复。

**看不全输出？** 长命令已完整换行显示，长输出点卡片底部的「展开全部输出」即可查看全部。

**结论只有半句 / 出现「阶段结论」？** 半句会自动续写补全；「阶段结论 · 已达最大步数」表示
跑满了 Agent 步数上限（后端固定 20 步），把步数上限调大再跑即可，详见第六节末尾。

**登录后立刻被踢回登录页？** 检查系统时间是否正常（Cookie 有效期依赖时间）、
以及是否用了无痕模式等禁用 Cookie 的环境。

**端口被占用？** 改 `config/config.json` 的 `server.port`，重启服务。

## 十二、本地终端审计（会话窗口 · 终端内容 1:1 全量实录）

顶栏 **「🧾 审计日志」** 打开审计面板。审计日志不存数据库，全部是本机可直接用记事本打开的
UTF-8 纯文本，按「会话窗口」分文件保存。

**一个会话窗口 = 一次「连接 → 断开」**，每次点主机「连接」就新建一个文件，点「断开」时封存：

```
ai-ops-console/audit/sessions/<登录用户名>_<连接时间>.txt   ← 1:1 可读实录
ai-ops-console/audit/sessions/raw/<同名>.raw                 ← 未经处理的原始字节流
例：admin_2026-11-13_19-50-01.txt
```

同一秒内重连会自动追加 `_2`、`_3`，不会覆盖已有文件。文件结构：

| 区域 | 内容 |
| --- | --- |
| 文件头 | 登录用户名、来源 IP、主机名称、目标地址、会话 ID、连接时间、终端尺寸、状态 |
| 终端实录 | **自连接建立起终端屏幕上打印过的全部内容**（登录横幅、命令回显、命令输出、报错、提示符、全屏程序画面），按显示顺序 1:1 转录为纯文本，不删减、不截断；仅去掉颜色 / 光标定位等不可见控制码 |
| 事件标注 | `# [事件] 时间 \| type=类型 \| source=来源 \| cmd=操作内容`，带精确时间戳，标注连接断开、上传下载、AI 代执行与登录登出 |
| 文件尾 | 断开时间、持续时长、终端实录行数 / 字符数、原始流字节数、事件条数、结束状态 |

**采集点不可绕过**：SSH reader 线程每收到一个字节块就回调 `audit.feed_output()`，先原样写
`.raw`，再把 UTF-8 文本送进 `TerminalTranscript`（`backend/term_capture.py`，模拟 xterm 的
cols × rows 屏幕：中文宽字符、CR/LF/BS/TAB、CSI 光标移动、清屏滚屏、备用屏幕、跨数据块
拆分的转义序列），逐行写入 `.txt`。**与浏览器 SSE 是否连接无关**，关页面也照样落盘；
写完一行立即刷盘，会话进行中打开 txt 就能看到实时增长的内容。前端自己打印的本地提示
（正在连接 / 连接失败 / 输出流中断）也通过 `/api/terminal/notice` 进入同一个窗口文件。

除终端实录外，按键流还原（`feed_keys`，支持退格 / 粘贴多行 / Ctrl+C，历史键与 Tab 补全
如实标注）、连接与断开、文件上传下载、AI 代执行命令、AI 诊断问答、控制台登录登出都会写成
结构化事件；无终端会话时按「用户名 + 当天」写入 `独立操作` 文件，保证记录不丢。

- **脱敏**：`-p密码`、`--password`、`token`、`Bearer`、URL 内嵌口令统一打码；`passwd` / `sudo -S`
  等交互式口令的下一行整体替换成 `[已脱敏：疑似口令/敏感输入]`。终端不回显的口令输入本来
  就不会出现在记录里；`.raw` 是未脱敏原始流，请按敏感文件保管。
- **异常退出兜底**：服务重启时，上次没收到断开请求的窗口会被自动补写「异常终止」结束摘要，
  不会出现永远「进行中」的半截文件。
- **界面**：左侧是会话窗口列表（默认选中最新一个），右上显示该窗口的完整原文，右下是跨所有
  窗口的检索表格（可按命令 / **终端输出原文** / 用户 / 主机 / IP / 会话文件名搜索、按类型过滤）。
  支持复制目录路径、打开目录、下载单个会话 txt、下载对应 `.raw` 原始流、导出全部，
  以及一键「让 AI 分析这些记录」。单文件预览超过 100 万字符时限流并提示下载全文。
- **问 AI 审计**：命中审计意图（含「审计 / 操作记录 / 执行过 / 谁 / 什么时候」等）时，后端会自动
  扫描整个 `audit/sessions/` 目录，把会话元信息、结构化事件**以及终端实录摘录**注入提示词作为
  **唯一事实依据**，AI 只能据此回答，没有的记录会明确写「审计文档中未找到」，不会编造。
  示例：`审计：admin 今天执行过哪些命令？`、`审计：cat xxx 那次输出了什么？`
- **接口**：`GET /api/audit/sessions`（清单）、`/api/audit/session?file=`（单文件全文）、
  `/api/audit/query`（跨文件检索）、`/api/audit/download?file=`（下载）、
  `/api/audit/raw?file=`（下载原始流）、`POST /api/audit/reveal`（打开目录）、
  `POST /api/terminal/notice`（前端本地提示上报）。文件参数只接受纯文件名并校验后缀，杜绝目录穿越。

> 早期单文件版 `command-audit.log` 已于 2026-11-13 归档到 `audit/archive/`（仅测试记录）。
> 新版只读 `audit/sessions/`，会话列表不再混入旧文件；若从旧版本升级且根目录仍有
> `command-audit.log`，其记录仍会被检索读到，但不会显示为一个会话窗口。

## 十三、运维工作台（轻量数据观察 · 只读）

顶栏切换到 **「📊 运维工作台」** 即可打开，与原有 SSH 终端、AI 助手、SFTP、审计**完全并存**：

功能按《基于 DeepSeek Harness 打造轻量级运维工作台》的呈现方式落地，但

- 监控数据 = 点顶栏「**⌁ 采集监控数据**」后，通过 SSH 对这些纳管主机执行一条只读命令

没有纳管主机、或还没采集过时，四项指标一律显示 **0** 并给出空态提示，**绝不用示例数字填充**。

| 区块 | 内容与口径 |
| --- | --- |
| 一屏总览 | 主机总数 = 纳管主机数；覆盖率 = 有监控快照的纳管主机 ÷ 纳管主机；活跃告警 = 所选时间窗内的采集告警；资产数据质量 = 逐台纳管主机检查 6 类字段缺失的合计 |

| 纳管主机资产台账 | 逐台列出已纳管主机**已填写的资产参数原值**（地域 / 机房 / 业务线 / 应用等级 / 组织 / 维保 / 维保状态 / 监控状态），未填写显示「—」。用来确认「主机参数确实被读到」；与质量清单互补：台账看**已填的值**，质量清单看**缺哪些字段** |
| 资产全量治理 | 六个维度：主机数差异（无监控快照）、未设置机房 / 业务线 / 应用等级 / 组织、维保到期；点任一维度下钻到**具体纳管主机**（名称 / 地址 / 地域 / 字段 / 问题说明），支持翻页。**全部为 0 表示字段已填齐、没有待治理项，不是没读到数据** |
| 最新采集指标 | 直接列出每台纳管主机**最近一次采集到的真实值**（CPU / 内存 / 磁盘 / 网络错误 / 采集时间）；采集成功但未超阈值时告警为 0 属正常，此处仍能看到数据，不会一片空白。≥85% 标黄、≥90% 标红 |
| 监控日清 | 时间窗可选 **最近 5 / 10 / 15 / 30 分钟 / 1 小时 / 自定义起止**；CPU / 内存 / 磁盘 / 网络四类按采集指标阈值判定：CPU、内存、磁盘 ≥85%，网络错误增量 >10；≥90% 记「严重」，同主机同类指标 10 分钟内不重复；点「查看全部告警」按当前窗口下钻 |
| 可插拔插件 | 内置 3 个只读插件：资产全量治理、监控日清、监控覆盖率对账。新增维度只需在 `backend/workbench.py` 注册一个插件定义，不改终端与审计链路 |
| AI 一键分析 | 总览和下钻明细都能「让 AI 分析」：自动把统一口径的明细（含当前窗口与最新采集指标）写进右侧 AI 面板并提问，沿用现有 AI 接入 / 模型 / 流式渲染 |

**补齐资产字段**：在左侧主机列表点「修改」，可填写地域、机房、业务线、应用等级、责任组织、
维保到期。其中**应用等级是四级下拉**（一般 / 重要 / 关键 / 核心），历史自定义值会保留为「原值（历史值）」。
**修改主机时密码留空表示不修改原密码**（与输入框提示一致），只有新增主机才要求密码必填。
表单保存后若当前在工作台视图会自动重绘，资产维度立即同步；**监控指标需重新点「采集监控数据」才会更新**。
「资产数据质量清单」是全为 0 且提示「字段已填齐」属正常——它只统计**待治理的缺项**；
要看你填进去的具体值，请上方「纳管主机资产台账」，那里逐台回显保存的参数原值。
顶栏「⟳ 刷新」只重读本地快照与配置，会显示耗时与刷新时间，不重新采集远端。

**权限做减法**：工作台只看、只比对、只下钻，**不重启服务、不下发配置、不进入执行链路**。
采集只执行只读命令，不对远端做任何修改；采集过程写入本机快照，不经大模型，也不进 AI 上下文以外
的执行链路。外部 CMDB / 监控的只读 GET 接口仅作预留对账，Token 只存本机配置、不回传前端，
「测试连通」仅发送 GET 请求；远程字段映射属于插件职责。

**注意**：差集只说明两端数据对不上，不判断哪端有误——新增未采集、下线未清理都会产生差异，
归因仍需人工判断；覆盖率的分母为纳管主机数，分母质量决定该指标有效性；
告警级别沿用团队既有规则，模型不参与告警定级。

接口：`/api/workbench/overview`、`/regions`、`/alerts`、`/plugin/run` 均接受
`window=5m|15m|30m|1h|custom` 与 `start`/`end`（自定义起止）；另有

### 3. 日志中心

- **日志管理**：用户指定「已纳管主机 + Linux 绝对路径 + 分类 + 可选告警关键词 + 可选链路正则」，
  支持增删改；默认空，路径中的 shell 特殊字符一律拒绝。
- **日志采集**：只对配置的路径执行只读 `tail -n N -- <path>`，日志原文、级别与采集时间落到
  `data/ops-logs.json`（已 gitignore）；采集失败如实显示原因，不补造日志。
- **日志查询 / 数据慢日志 / 业务访问日志**：按分类、级别、关键词查询真实采集行。
- **日志告警**：只统计用户在日志源中填写的关键词对真实日志行的命中数。
- **日志链路**：用户配置的正则从真实日志行提取链路标识后按链路分组；未配置正则时为空。

## 十五、主机统一管理 / 运维大屏 / 数据库与告警中心

### 1. 主机入口收敛

- SSH 视图左侧旧「主机列表」竖条已移除，主机统一在工作台 **资产管理 → 主机管理** 中管理：
  新增、编辑、删除、导入（JSON / CSV）、导出（脱敏 JSON）。
- SSH 终端顶部保留一个紧凑的主机选择与「连接 / 断开 / 管理主机」工具条，原有 SSH 会话、
  SFTP、审计链路不变。
- 导出文件只含台账字段与最新采集指标，**不含密码或口令散列**；导入时按地址 + 用户名定位
  已纳管主机，密码留空不覆盖原密码，错误条目逐条返回且不阻断其它条目。

### 2. 运维大屏

顶栏「🖥 大屏」打开铺满整个浏览器的态势展示页（亮蓝紫 + 青绿 + 琥珀配色，与工作台浅色主题、
参考站深蓝黑主题均不同）：活跃告警、告警趋势、资产构成、地域分布、主机 CPU / 内存 / 磁盘实时
态势、监控覆盖率环形图。所有数字来自 `/api/ops/screen` 对纳管主机快照、真实告警和用户台账的

### 3. 全局刷新

顶栏「⟳ 全局刷新」与仪表盘 / 各功能页的刷新按钮现在会重读：主机清单、采集快照、告警、
资产台账、日志内容、当前页面以及大屏（若打开），并显示「全局刷新完成」与耗时。此操作只
同步本地真实数据；若要改变 CPU / 内存等监控值，仍需先点「采集监控数据」从主机只读采集。

### 4. 新增功能页

- **平台导航**：置于左侧菜单最上方（不在任何分组内，点击展开；刷新后仍在原位）。页面只保留
  资产 / 容器 / DB 数据库 / 日志中心 / 告警中心 / 系统管理六个入口，其中资产 / DB / 日志 / 告警
  四个橙框入口已接入，容器与系统管理只占位、不展示模拟数据。原来红框标注的配置中心、
  服务作业、AIOps 运维、工单中心、费用中心、审计中心六个占位入口已移除。
- **DB 数据库** 分组：数据资产、SQL 查询、SQL 审核、监控概览（慢日志分析、数据库助手入口已去掉）。
  查询与审核记录由用户录入或粘贴，**系统不假装执行 SQL**；监控概览只显示数据库资产关联的
  纳管主机的真实采集指标。数据库资产清单按「实例名称 / 类型 / 版本 / IP-端口 / 环境 / 业务系统 /
  监控接入 / 存活状态 / 认证状态 / 操作」排列；「监控接入」由是否关联纳管主机且有真实快照得出，
  其余字段全部由用户录入，没有写死任何示例数据。冷启动直接进入本页时「新增资产」按钮也能打开弹窗：
  台账字段元数据改为按需加载，不再依赖先访问主机管理页。
- **日志中心**：日志源路径须为纳管主机上的 Linux 绝对路径。系统日志常见路径是 `/var/log/messages`
  （不是 `/var/log/message`）；链路提取正则正确写法为 `(trace[=:]([a-z0-9-]+))`，填写错误或留空时
  日志行照常采集，只把链路标识留空，不会导致整源失败。
- **运维大屏**：顶部可切统计窗口（5 / 10 / 15 / 30 分钟 / 1 小时），CPU / 内存 / 磁盘指标带 `%`

  探测主机，检测在该主机上执行只读 `curl` / `openssl`，失败原因如实回写。
